# Large-model stress campaign — 27 September 2026

This campaign deliberately increases size and difficulty beyond the small demonstration suite. Public baseline solvers run as separate comparison processes; none is a dependency of the VANTAGE optimization engine.

## Selected models

| Model | Class | Purpose |
|---|---|---|
| Netlib dfl001 | LP | Difficult first-order convergence and degeneracy |
| Netlib stocfor2 | LP | Structured stochastic-programming LP |
| rail507 continuous relaxation | Derived LP | Large number of columns; explicitly not the integer benchmark |
| rail03 continuous relaxation | Derived LP | Approximately 759,000 columns and 1.73 million nonzeros |
| planted_1m | Synthetic LP | One million columns, 500,000 rows, 1.5 million nonzeros; known optimum |
| MIPLIB rail507 | MILP | Public railway instance, incumbent and certified-bound comparison |
| MIPLIB rail03 | MILP | Large sparse railway instance |
| MIPLIB ns1644855 | MILP | Over two million matrix nonzeros |

[MIPLIB rail03](https://miplib.zib.de/instance_details_rail03.html), [rail507](https://miplib.zib.de/instance_details_rail507.html), [ns1644855](https://miplib.zib.de/instance_details_ns1644855.html), and [Netlib collection](https://www.netlib.org/lp/data/) describe the public instances. Download manifests retain source URLs, exact bytes and SHA-256 checksums. LP relaxations remove integrality through a benchmark-only HiGHS conversion call; no optimization occurs during conversion.

The planted LP is generated by [generate_sparse_stress.py](../examples/generate_sparse_stress.py). Its expected objective is 3,437,485 for one million variables and seed 42. It stresses sparse data handling and throughput, but its deliberately known optimum makes it easier than arbitrary industrial problems. It must never be described as actual MRPL data.

## Protocol

Exploratory stress runs use one measured run, a separate CUDA warmup, 60 seconds of solver budget, four requested CPU threads and tolerance 1e-6. They are screening experiments, not statistically established speedups. A process watchdog allows 30 additional seconds for parsing/startup/output; standalone verification runs separately. End-to-end solver time and complete process wall time are retained separately.

LP comparisons use the same explicit PDHG method on our CPU and CUDA implementations, with CUDA graph execution and device monitoring. HiGHS selects its own algorithms. MILP comparisons use our automatic relaxation selection, reliability branching, cuts and heuristics, against HiGHS and SCIP 10.0.2. SCIP supplies primal solutions and tree bound/gap telemetry but no LP duals in this adapter; it is used only for MIP incumbent verification.

Every result, including timeouts, numerical failures, missing incumbents and verification failures, remains in CSV and raw JSON. An OPTIMAL LP/QP result counts as solved only after the standalone original-space verifier accepts it. Integer verification checks incumbent feasibility; a claimed global optimum additionally relies on each solver's tree bound logic, not an independently replayed proof.

Timing was collected on a laptop with ordinary desktop applications still running. Hardware, background process snapshot, source checksums, build settings, measured executable and model copies are retained in each campaign directory. Treat small timing differences cautiously. Do not compare a single run with literature timings on other hardware.

## Reproduction

Install the comparison-only dependencies from `benchmark/requirements.txt`, build the solver, then run:

```bash
VANTAGE_BINARY=build/vantage ./scripts/run_stress_campaign.sh
```

The script downloads data, generates the planted model, derives the railway LP relaxation, and executes the LP and MILP campaigns sequentially. Internet is needed for initial dataset acquisition. Each campaign generates HTML and performance-profile artifacts from retained records. Allow several gigabytes of disk space for large input/solution snapshots.

Current local campaigns are `results/stress_lp_20260927` and `results/stress_mip_20260927`. Their tables and limitations will be archived under `docs/evidence/` after all selected runs finish.

## Harness and parser findings

The first screening campaign used 10-second inspection and 20-second standalone verification watchdogs. The larger files exceeded these allowances, and CUDA planted-model verification was interrupted despite finite excellent internal residuals. `benchmark/reverify.py` replays verification with 90 seconds, producing `runs.reverified.csv` and checksummed verification records without altering the original timing/status CSV. Later campaigns expose configurable 60-second inspection and verification budgets.

The initial public MILP campaign caught an input interoperability bug: four-token bound records with values far to the right were incorrectly reinterpreted as fixed-column records, truncating their values. The reader now preserves complete four-token records and reserves fixed-column recovery for records with missing fields. A regression test reproduces the rail507 bound layout. That partial campaign was stopped and retained with an explicit diagnostic stop record; corrected public-MILP measurements use a fresh campaign directory.
